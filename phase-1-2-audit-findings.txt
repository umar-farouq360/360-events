BLOCKING ISSUES
---------------

1. MISSING MIGRATIONS FOR PHASE 2 TABLES

   Only migrations 0000-0003 exist (apps/api/src/db/migrations/meta/_journal.json).
   There is no migration for:
   - notifications
   - notification_attempts
   - rate_limits

   A fresh db:migrate leaves these tables absent, which directly causes the failing
   tests:
   - apps/worker/tests/notification-handler.test.ts
     Error: relation "notification_attempts" does not exist
   - apps/api/tests/security-middleware.test.ts
     Error: relation "rate_limits" does not exist

   This breaks P2-T06 and P2-T07 on a clean environment.

2. SECURITY AND AUTHORISATION MIDDLEWARE ARE NOT WIRED INTO THE APP

   apps/api/src/app.ts:6-12 only installs logging, JSON parsing, health routes and
   the 404 handler. It never calls:
   - configureSecurity(...)
     Therefore helmet, CORS, body limits and raw-body support are not active.
   - registry.verifyNoUnregisteredRoutes(app)
     Therefore deny-by-default is not enforced at startup.

   The route registry, rate limiter, validation helper and auth middleware exist only
   as isolated modules/tests. P2-T07 and P2-T08 are not delivered in the running API.

   Also, checkOwnershipOrNotFound throws an error with status = 404, but
   apps/api/src/middleware/error.middleware.ts:28-39 always returns 500 for anything
   other than InvalidTransitionError. The documented 404-vs-403 convention does not
   work yet.

3. LINT IS RED

   pnpm lint fails because:
   - apps/worker/src/lib/email.js and email.d.ts are committed generated artifacts
     under src/
   - apps/worker/tests/notification-handler.test.ts uses cross-app relative imports
     without .js extensions:
       ../../api/src/db
       ../../api/src/db/schema/index
   - eslint.config.mjs contains apps/api/tests/helpers/*.ts twice

4. CI/DEPLOYMENT PIPELINE IS NOT FUNCTIONAL

   - CI database port is wrong: service maps 5435:5432, but DATABASE_URL uses
     localhost:5432 (.github/workflows/ci.yml:22,30).
   - CI runs db:generate before db:migrate. If migrations are missing (as they are
     now), CI silently generates them instead of failing.
   - pnpm verify does not run a build, contrary to the plan and PR template.
   - Staging deployment is entirely mocked with echo statements
     (.github/workflows/deploy-staging.yml:37-57).
   - API Dockerfile runs apps/api/dist/server.js, but no server.ts exists; build
     output is dist/index.js (apps/api/Dockerfile:37).
   - Database role separation exists only in docs/database-roles.md; no roles/grants
     are implemented.

5. TEST HARNESS AND DRIFT CHECK ARE WEAKER THAN REQUIRED

   - apps/api/tests/harness.ts only opens connections; it does not isolate a database
     per run, apply migrations, or truncate between tests.
   - harness.test.ts does not demonstrate row-lock contention, only two independent
     SELECTs.
   - drizzle-kit check is not a true schema-vs-migration drift detector.
   - Concurrency suites run once, not the required 20 consecutive repetitions.

6. REQUIRED DOCUMENTATION IS MISSING

   Phase 1/2 exit criteria and Phase 3 entry depend on these, but they do not exist:
   - docs/state-machines.md
   - docs/decision-register.md
   - docs/database-design.md
   - docs/api-contract.md
   - docs/security-and-privacy.md
   - docs/adr/

P2-T07 Security middleware and rate limiting — NOT MET
