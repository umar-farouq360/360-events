# ADR-023: Identifiers

Status: Accepted (refinement proposed)
Recorded: 2026-11-14 (accepted baseline: `implementation-plan.md` §4.2)
Unblocks: every schema task
Satisfies: ARCH §6.4; non-guessable identifiers (BR §12.2)

## Context

Primary keys must be non-sequential (no enumeration), index-friendly, and generated by the application so ids exist before insert (needed for outbox and idempotency flows). Customers also need a short, human-readable order reference for support.

## Options considered

| Option | Notes |
|---|---|
| Serial integers | Enumerable, leak volume. Rejected. |
| UUIDv4 | Non-guessable but random, so poor B-tree locality. |
| **UUIDv7** | Time-ordered, non-guessable enough for resource ids, good locality. Chosen. |
| ULID / nanoid | Not a native PostgreSQL type. |

## Decision

- Every table's primary key is a UUIDv7 generated in application code (`uuidv7` package).
- Order references shown to people: `360-` followed by 10 characters of Crockford base32 (no `I L O U`), random, stored in a unique column, regenerated on collision. They are not secrets and not used for authorisation.
- Ticket credentials are separate from ticket ids (ADR-026).
- IDs are opaque strings in the API. Clients never parse them, and no feature may depend on their time ordering.

## Proposed change (needs your acceptance): native `uuid` column type

The current Phase 2 tables declare primary keys as `text`. Use PostgreSQL's native `uuid` type instead, for all tables.

Why: 16 bytes instead of 36, smaller indexes and foreign keys everywhere, and the database rejects malformed ids. Drizzle accepts the same string values from the `uuidv7` package, so application code barely changes. Converting is nearly free now, because no production data exists. It becomes a risky expand/contract migration once real rows exist.

Affected existing tables: `audit_events`, `outbox_events`, `idempotency_keys`, `notifications`, `notification_attempts`, `rate_limits`, `db_migrations_history` (check each for a text key).

## Consequences

- Foreign keys must also be `uuid`.
- Test fixtures must generate valid UUIDs.

## Revisit trigger

A requirement for ids that embed a shard or tenant; the platform adopts UUIDv7 support in PostgreSQL natively (then drop the library).
